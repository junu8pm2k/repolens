# 2026-11-16 聊天可用性修复

## 已复现的问题

- 每个原生工具复用完整参数表，导致查询 Issue 标题也重复发送工作区、记忆、会话和分析参数。
- 标题查询、问号及打招呼都执行文档预检索；旧任务摘要也被注入，容易把当前对话带回 CI 调查。
- 输入诊断混用原始历史、组装上下文和完整模型输入，最终总结未绑定工具时仍计算工具定义。
- 仅靠提示词约束“只输出标题”不稳定：重复真实回放出现附加证据说明。

修复前新增的定向回归中，8 项失败、1 项通过，覆盖参数膨胀、无关预检索、字段投影和输入计量。

## 修复

- 为各工具生成独立参数 schema，当前仓库和会话 ID 继续由服务端注入；删除提示文本中重复的工具说明。
- 明确的结构化字段查询跳过文档预检索、证据索引重建、历史摘要注入和无关历史压缩；文档及调查请求保留预检索，Agent 的检索工具也仍可使用。
- 简单问候直接调用模型，不绑定仓库工具，不注入旧任务历史。
- Issue 读取支持 `fields` 投影；文本结果保留换行，不再把正文转义成一整段 JSON。
- 对“直接输出/只输出”单一字段的明确要求，运行时从成功工具结果返回原值，并核对用户指定的 Issue 编号；不再让第二次模型总结添加内容。
- 输入占用优先采用最后一次调用的供应商 usage；缺失时使用完整输入估算。历史、资料和工具定义分别标明估算口径，未绑定工具的调用不计工具 schema。
- 页面保留可展开的诊断及工具记录，取消回答下方的内部 route 字段，不展示未启用的预检索卡片。

## 最终真实回放

使用用户授权的现有 DeepSeek 配置，复用原会话问题与历史并按生产预算压缩；不向原会话追加消息。以下是最终版本单次回放，不能作为所有问题的稳定通过率。
