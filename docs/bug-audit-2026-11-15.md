# RepoLens AI 缺陷检查与修复记录

本轮在现有工作区继续检查，保留此前未提交的修改。检查范围包括全部后端测试、前端生产构建、RAG 问答、Git 实时查询、GitHub 同步和前端异步状态。

## 本轮修复

| 问题 | 触发及影响 | 修复 |
| --- | --- | --- |
| PR 同步错误清空旧数据 | 拉取文件或评论遇到 HTTP 错误时，旧数据已经删除 | 拉取成功后才替换；超时或 HTTP 错误保留旧数据；成功返回空列表仍正常清空 |
| 跨仓库与跨会话请求竞态 | A 的请求晚于 B 返回，覆盖 B 的记录或回答；清空会话后旧回答重新出现 | RAG 工作室使用请求代次与仓库标识；工作台历史和项目数据校验当前范围；安全草稿页隔离加载并显示错误 |
| LLM 异常打断已有回退 | 网络超时、断连、无效 JSON 或错误响应形状逃逸为请求错误 | 非流式文本客户端返回空文本，RAG 继续按已有证据摘录逻辑返回答案和引用 |
| 提问向量化阻塞事件循环 | 在 async 检索函数里同步加载模型或编码，其他请求无法及时运行 | 将无数据库操作的查询向量化移入工作线程 |
| SSE 解析兼容性及资源释放 | CRLF/CR 换行、无空格 data 字段、跨字节拆包使事件丢失；回调错误后 reader 未释放 | 按行解析协议，支持不同换行及拆包；异常时取消并解锁 reader |
| 最新 commit 意图过宽 | 最近提交的 Issue、最近 100 次提交、修改文件问题被误当成单条提交时间 | 排除其他业务对象、多条历史和文件变化请求，保留原文档处理路径 |
| 检索 trace 配置不准确 | 单次关闭重排或过滤，trace 仍展示知识库默认开启状态 | 返回该次请求实际使用的方法、重排、过滤开关和门槛 |

同时更新了仍断言默认门槛为 0.8 的旧测试。当前默认门槛已是 0.5，相关测试继续验证低分资料会被过滤。

## 验证结果

- 后端完整测试：268 项通过。使用隔离的 SQLite、确定性 embedding 与假 HTTP 传输，不修改运行中的 PostgreSQL/Milvus。
- 前端接口测试：3 项通过，覆盖各种 SSE 换行、UTF-8 逐字节拆包、取消解锁和 API 错误消息。
- 前端 `npm run build`：成功，包含生产编译、类型检查、lint 和 17 个页面的构建。
- 针对 Git 实时事实、冲突判定和来源隔离的既有回归继续通过。
- 重启后的正式服务检查：健康接口、仓库列表、RAG 仓库列表及 RAG 页面均返回 200。
- 原问题“这个项目是干什么的”返回 `llm` 回答和 5 个引用，冷启动耗时约 17.2 秒；模型加载期间健康接口响应约 559 毫秒。
- “最近一次commit是什么时候”返回 `direct` Git 查询与 1 个引用。
- 生产数据完整性：309 个资料切片与 309 个 Milvus 向量逐条对应，未发现缺失或过期向量。
