# 团队仓库资源同步架构决策记录

状态：V1.0 待评审。需求和技术结构分别见 [PRD](PRD.md) 与 [ARCHITECTURE](ARCHITECTURE.md)。

## ADR 001 以本地 Git 提交作为同步输入

**背景**　成员已经通过 Git 获取团队仓库。预览和应用需要引用相同版本，才能解释每次投递来自哪里。

**决策**　同步命令在预览时固定本地团队仓库的 `HEAD` 提交 SHA，以 tree 和 blob 读取内容。确认时应用预览中的版本，并在结果中展示该 SHA。

**备选与影响**　直接扫描工作树能立即看到成员正在编辑的内容，也会把这些改动带入共享版本。由服务端读取远端仓库适合集中分发，需要接入远端身份与网络。当前选择保留成员现有的 Git 更新步骤，并让已获取的提交可在本地重现。PoC 已验证未提交改动与固定快照的差异。

## ADR 002 采用 Codex 项目原生文件

**背景**　首版只支持 Codex CLI。Skill 需要随任务调用，项目级规则和团队指令需要在新会话中可加载。目标项目通常已有自己的约定。

**决策**　Skill 交付到项目 `.agents/skills/`。Rule 和共享指令来自各自的源目录，按稳定顺序写入根 `AGENTS.md` 的团队管理区块。两类内容在区块内各有小节。`paths:` 的目标格式在 V2.0 评估。

**备选与影响**　在 RepoLens 聊天中加载资源可复用应用内 Skill Runtime，适合从 Web 应用调用。写入用户全局 Codex 配置可覆盖多个项目，需要额外管理项目间的作用范围。项目原生文件让同步结果直接服务于目标工作区，也要求对同名文件、管理区块和新会话加载进行验证。PoC 已验证 Codex 的原生发现与上下文加载。 [目标文件约定](ROADMAP.md)

## ADR 003 用本地清单管理覆盖、移除和恢复

**背景**　目标项目可能已有同名资源，且一次同步涉及多个文件。删除前需要确认归属，中断后需要区分上一次完整应用和未提交的写入。

**决策**　在目标项目本地维护受管理路径和摘要。预览与应用都核对实际内容。应用持有项目锁，先留存恢复数据，再逐文件替换，以更新清单作为完成标记。索引刷新在文件阶段结束后独立进行。

**备选与影响**　按文件名直接覆盖实现最短，无法证明内容是上次同步产物。把本地文件状态放进服务端数据库可以集中查看，需要本地与服务端共同处理写入中断。采用本地清单后，成员失去清单时需重新确认冲突内容归属，文件冲突也能在调用索引前解决。PoC 已验证同名冲突、手动修改与重复同步，恢复流程进入实现验收。

## ADR 004 将文档镜像放在项目 docs 并复用索引

**背景**　PoC 证明目标项目 `docs/` 下的镜像能被现有索引发现，隐藏镜像目录和 `sharing/docs/` 则未被发现。文档需要和 Skill、规则与指令分别交付。

**决策**　首版默认镜像目录为 `docs/team-shared/`，可通过 `sharing.docs.localDir` 指向目标项目 `docs/` 内的目录。沿用仓库级项目索引，在索引事务里保存团队仓库路径、来源提交和索引完成的文档清单摘要。

**备选与影响**　任意镜像目录提供路径灵活性，需要扩展现有发现规则。新建团队文档索引便于独立管理增量和权限，也会增加另一套存储与失效流程。复用项目索引能沿现有流程处理更新和删除。目标项目的索引配置仍会影响覆盖范围，扫描状态需显示被排除的文档。文件应用成功后，索引故障可以单独重试。 [项目索引实现](../../backend/app/services/project_indexing.py)

## ADR 005 为 Codex 提供独立的 recall 返回契约

**背景**　现有检索内部保留路径元数据，现有 MCP 文本响应只投影检索摘要。若按镜像名返回路径，队友无法据此找到团队仓库里的原始文档。

**决策**　在现有本地 RepoLens MCP 进程中增加 `recall`。查询所传 `repo_id` 必须匹配已绑定的目标项目。复用检索逻辑，并从索引结果读取标题、片段、团队仓库内路径和来源提交。团队文档过滤发生在结果排序和截取之前。

**备选与影响**　扩充现有通用证据工具的文本格式可以减少工具数量，现有调用方也需要适配输出变化。单独部署文档服务可以独立控制接入，需要运行另一个进程。使用既有 MCP 进程中的独立工具契约，保留通用证据工具对现有调用方的行为，首版需完成一次 Codex 本地接入和实际调用验收。 [现有检索](../../backend/app/services/chat_memory.py) · [现有 MCP 服务](../../backend/app/mcp/memory_server.py)
