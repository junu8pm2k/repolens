# 团队仓库资源同步路线图

MVP 范围与版本排期 · 评审稿

## 产品目标

团队在一个 Git 仓库维护共享 Skill、规则、工作指令和文档。成员用一个本地命令把选定提交同步到当前项目，即可在 Codex CLI 中复用同一套流程和约定，并通过 `recall` 查阅团队文档。首期验证两位队友能否从同一份团队资源出发，完成一次真实 PR 审查。

## V1.0 MVP

固定 **一个团队源仓库、一个目标项目、一个工具、一个手动同步入口**。成员沿用现有 Git 流程更新本地团队仓库，同步命令读取该仓库当前已提交的 `HEAD`。本地预览展示来源 SHA 和目标文件的新增、更新、移除与冲突，成员确认后应用。

### MVP 范围清单

| 资源 | 团队仓库位置 | V1.0 交付结果 |
| --- | --- | --- |
| `skills` | `skills/<name>/SKILL.md` | 将说明和必要的文本参考资料投递到目标项目 `.agents/skills/<name>/`，在需要时选用。 [Codex Skills](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills) |
| `rules` | `rules/<name>.md` | 将项目级常驻约束写入根 `AGENTS.md` 的团队管理区块。带 `paths:` 的条目在预览中标记为 V2.0 支持。 |
| 共享指令 | `agentsmd/*.md` | 将共享工作步骤、输出要求或协作约定写入同一管理区块，在区块内保留独立的指令小节。 [Codex 项目指令](https://learn.chatgpt.com/docs/agent-configuration/agents-md#how-codex-discovers-guidance) |
| `docs` | `docs/` 下的 Markdown 文档 | 镜像到 `sharing.docs.localDir`，复用项目文档索引供 `recall` 检索，并返回仓库内来源路径。 |

规则和共享指令保留各自的源目录，复用同一个写入目标。同步更新和移除限于工具管理的内容。遇到个人维护的同名文件，或上次同步的内容被手动修改时，预览列明冲突，由成员处理后重试。

### 首期闭环与验收

1. 贡献者提交 PR 审查 Skill、一条 API 兼容性规则、一段审查输出指令和一份接口迁移说明。
2. 队友预览变更并应用，在目标项目开启新的 Codex CLI 会话。能发现并显式调用 Skill，按共享规则和指令完成审查，再用 `recall` 找到迁移说明并查看来源。
3. 贡献者更新规则、撤下一条指令并修改迁移说明。队友再次同步，能看到变更与来源 SHA，工具内容和检索结果都反映最新版本。移除文档后，成功同步会更新镜像和索引。重复应用同一提交，结果显示「无变化」，本地同名或手动修改的内容会在预览中标记为冲突。

## V2.0 迭代路线

| 顺序 | 增量 | 交付结果 |
| --- | --- | --- |
| 1 | 规则作用范围 | 支持 `paths:`、`rules/<name>/RULE.md` 及路径匹配验证。工具无法等价表达作用范围时，预览标明对应条目。 |
| 2 | 第二个 Agent 工具 | 按试点反馈选择一个团队常用工具。同一资源仓库可投递到第二个工具，验证单文件 Skill 与 `claudemd`、`culture.md` 等来源格式。 |

产品界面、自动同步与跨项目订阅作为后续候选。`agents`、`env`、`hooks`、`mcp`、`models`、工作流及其 `prompts`、`scorers`、`benchmarks`，以及 `learnings` 和 `wiki`，在团队实际使用需求明确后再排序。

## 版本排期

以下按一位开发者连续投入估算，以范围确认后的开工周为第 1 周。V2.0 排期基于 V1.0 试点通过。

| 版本 | 相对排期 | 阶段交付 |
| --- | --- | --- |
| V1.0 | 第 1 周 | 约定四类源路径，完成读取、核对来源和变更预览。 |
| V1.0 | 第 2 周 | 完成本地应用、冲突处理和文档索引接入，两位队友跑通首次使用和一次更新。 |
| V2.0 | 第 3 至 5 周 | 依次实现路径规则和第二个工具适配，每项以真实仓库验证后发布。 |
