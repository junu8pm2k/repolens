# 团队仓库资源同步产品需求文档

状态：V1.0 评审稿。范围与版本排期见 [ROADMAP](ROADMAP.md)。

## 背景与目标

团队可以把审查流程、规则、工作指令和文档放进同一个 Git 仓库。成员当前项目要用上这些内容，还需要知道文件放在哪里、何时更新，以及哪些文档可以检索。V1.0 提供一个本地同步入口，让成员在确认变更后，把团队仓库中同一份 Git 提交交付给目标项目的 Codex CLI 和 RepoLens 文档检索。

首期以 PR 审查验证产品价值。一位贡献者发布四类资源，另一位队友完成同步、调用审查 Skill、按团队约定输出结果，并从 `recall` 找到迁移说明和原始路径。之后两人再跑一次资源更新和撤下，确认团队能持续使用同一套约定。

## 用户与前置条件

| 用户 | 主要需求 |
| --- | --- |
| 团队资源贡献者 | 用现有 Git 流程发布、更新或撤下资源，队友可以按提交确认自己收到的内容。 |
| 项目成员 | 在当前项目查看将要发生的变更，确认后使用资源，同时保有自己维护的本地内容。 |

V1.0 围绕一个已拉取的团队源仓库、一个本地目标项目、Codex CLI 和一个手动同步入口。团队仓库通过成员现有的 Git 访问方式获取。文档检索使用 RepoLens 中已连接的目标项目。

## V1.0 资源范围

| 资源 | 团队仓库位置 | 成员收到什么 |
| --- | --- | --- |
| Skill | `skills/<name>/SKILL.md`，可附必要的 Markdown 或纯文本参考资料 | 目标项目 `.agents/skills/<name>/` 中可按需调用的任务包。 |
| Rule | `rules/<name>.md` | 目标项目根 `AGENTS.md` 团队管理区块中的项目级规则。带 `paths:` 的条目在预览中标记为待支持。 |
| 共享指令 | `agentsmd/*.md` | 同一个团队管理区块中的独立指令小节，可用于定义工作步骤、输出格式和协作约定。 |
| 文档 | `docs/` 下的 Markdown 文件，包含子目录 | 镜像到 `sharing.docs.localDir`，复用项目文档索引。`recall` 返回匹配内容和团队仓库内的来源路径。 |

V1.0 以目标项目现有 `docs/` 下的目录作为文档镜像的支持范围。团队文档镜像保留相对目录结构，检索结果应指回团队仓库中的原始路径。

## 核心流程

1. **发布。** 贡献者将资源提交到团队仓库。成员按团队现有 Git 流程拉取更新，准备好目标项目。
2. **预览。** 成员启动本地同步入口。工具读取团队仓库当前已提交的 `HEAD`，显示来源 SHA、目标项目和各资源的新增、更新、移除、冲突或待支持项。
3. **应用。** 成员确认后，工具按已预览的提交写入项目，更新受管理的文档镜像并刷新索引。结束时显示实际交付的资源、来源 SHA 和文档检索状态。
4. **使用。** 队友在目标项目开启新的 Codex CLI 会话，选用 Skill，按项目规则和指令执行任务。需要背景资料时，通过 `recall` 查看内容和来源。
5. **再次同步。** 团队发布更新或撤下资源后，成员用同一入口查看差异并应用。重复同步同一份已完整交付的提交时，显示「无变化」。

## 功能要求

### 同步预览与本地文件保护

- 同步以 Git 提交为输入，未提交文件留在成员工作区。预览每项包含资源类型、源路径、目标位置和处理状态，成员可以在应用前退出。
- 应用使用预览中的提交。若目标文件在预览后被改动，提示重新预览。首次遇到本地同名文件、先前同步的内容被修改或管理区块发生冲突时，显示具体位置并引导成员处理。
- `AGENTS.md` 只在团队管理区块内更新规则和指令。更新或移除其他文件前，要核对该文件是否由上一次同步管理。团队撤下资源时，预览明确标出将移除的内容。
- 带 `paths:` 的规则、超出首版格式范围的内容和无效资源在预览中展示原因。范围受限的规则只在支持其范围的版本中生效。若原来的项目级规则改成带 `paths:` 的规则，预览应同时显示旧项目级规则的撤下和新版待支持。

### 文档检索与恢复

- 关键词能够检索到已同步到当前项目的文档内容。返回结果至少包括标题、匹配片段和团队仓库内的相对路径。
- 文档更新并完成索引后，检索结果反映新内容。确认移除并完成索引后，旧文档退出当前项目检索。
- 文件交付和索引结果分别展示。文档索引失败时标记为待重试，并显示具体失败原因。成员可对同一提交补做索引，已交付文件不产生重复副本。

## 首版验收

| 场景 | 通过标准 |
| --- | --- |
| 首次同步 | 源仓库同一提交包含四类资源。队友能看到完整预览，确认后在目标项目获取对应交付结果。 |
| 完成真实任务 | 队友在新 Codex CLI 会话显式调用 PR 审查 Skill，输出遵循所同步的审查要求，并通过 `recall` 引用迁移说明及其来源路径。 |
| 更新与撤下 | 修改 Rule 和文档，撤下一段共享指令及一份文档。应用后，新会话使用新版内容，检索返回更新文档，已撤下的文档退出检索。 |
| 重复同步与冲突 | 重复同步已完整应用的提交时显示无变化。预览只列已提交的源文件，目标同名文件和本地修改均标记为冲突。 |
| 索引失败与恢复 | 索引异常时命令输出明确显示文档检索待重试。同一提交补做索引后，文档可检索且文件无重复。 |

试点记录成员从拿到仓库到首次使用的耗时、出现的冲突或人工操作，以及后续更新是否成功。两位队友完成上述场景后，进入 V2.0 评估。

## PoC 结论与版本衔接

PoC 已验证四类资源按 Git 提交读取并同步，Codex CLI 能发现 Skill 并加载规则和共享指令，项目文档新增、更新和移除可反映到现有检索。现有检索结果带文档路径，现有 MCP 文本响应需要补充该字段才能满足首版溯源要求。真实 PR 的模型输出留在试点中验收。 [项目文档索引](../../backend/app/services/project_indexing.py) · [现有 MCP 响应](../../backend/app/mcp/memory_server.py)

V2.0 继续验证 `paths:` 路径规则、扩展的资源格式和第二个 Agent 工具。版本排期与入口以 [ROADMAP](ROADMAP.md) 为准。
